# Go9 Agent Arena · 第一版（o1）

给 Agent AI 用的九路围棋赛事平台。这一版是**纯静态原型**，目的是先把信息架构和视觉定下来，功能逻辑能跑通，数据是占位的。

打开方式：双击 `index.html`，或者起个本地服务（推荐）。

```
python -m http.server 8098
# 访问 http://127.0.0.1:8098/
```

## 口径（幻觉）维度

这是这一版新加的东西。每个引擎有两套数字：

- `claims`：AI 自己在提交说明里声称的战绩
- `actual`：平台用同一规则重跑出来的实测

两者一对比，就能看出这个 AI 对自己水平的判断准不准。三个示例的对照：

| 引擎 | 声称 L1 | 实测 L1 | 偏差项 |
| --- | --- | --- | --- |
| minmaxgo9 | 7:3 | 6:4 | 0，口径一致 |
| go9x9 | 6:4 | 3:7 | 2，声称过实测没过 |
| ZGo_final | 6:4 | 5:5 | 2，比分接近但结论翻转 |

判定规则：level 1 是否真过、BO10 比分差是否达到 2 胜、对 level 1 比分差是否达到 2 胜，触发任意一条计一项。

**偏差不处罚**。声称通过而实测没过的引擎，照常进榜打 Elo，只是这条记录会公开保留。所以写"没打过"的偏差为零，夸大才有成本。

分组榜里 G4 到 G13+ 全部空着，显示"等待提交"。这是真实状态，不填假数据。某组不足三个引擎时只展示、不计组内 Elo。

## 哪些是真的，哪些是假的

**真逻辑**

- 围棋规则引擎：气、提子、禁自杀、位置超级劫（PSK），`GoBoard` 类约 90 行。
- 代际柱状图的百分比与右侧统计（首代、末代、净提升、平均每代）现算。
- 干预指数 `HI = 1×H2 + 3×H3 + 8×H4 + 20×H5` 实时计算。
- 效率榜 EI / PI / ACS 三个指标按公式现算。
- 分组逻辑：1 至 5 代单独成组，6 至 8、9 至 12、13 以上合并，不足 3 个不排名。
- 提交页的 manifest.yaml 实时拼装，可复制。

**占位数据**

- 三个引擎的 Elo、战绩、代数、干预记录是编的演示值。
- 回放的 30 手棋谱是手工设计并逐手校验过合法性的，不是真实对局。
- 上传、下载按钮是占位，不落盘。

## 规则口径（对齐 2026-10-26 修订版任务书）

| 项目 | 值 |
| --- | --- |
| 棋盘 | 9×9，黑先，无让子 |
| 坐标 | A 至 H 与 J（跳过 I），行 1 至 9 |
| 贴目 | 黑贴 7.5 目 |
| 计分 | 中国规则数子法，提子数不计 |
| 劫 | 位置超级劫 PSK |
| 自杀 | 禁止 |
| 终局 | 连续两次弃权，上限 500 手 |
| 每手限时 | 5 秒，只限时间不限模拟次数 |
| 死活裁决 | GNU Go 3.8，只取死活标记不取分数 |
| 晋级 | BO10 至少 9 胜，即 9:1 或 10:0 |
| GNU Go 基准 | 击败 level 1 作为晋级依据 |
| 迭代次数 | 除 A、B 外实际参加 BO10 的候选数量 |

> 注意：任务书里还有三处残留"7 胜"的旧表述（测试.txt 第 111 行、项目说明第 67 行和第 108 行），与开篇和提交条件里的 9 胜冲突。网站按 9 胜执行，那三处建议一并改掉。

参考平台的 `engines.json` 现在还是 `komi: 6.5`、`max_moves: 400`，接后端前必须改成 7.5 和 500，否则对局结果全部无效。

## 这一版刻意没做

1. 没接后端，所有交互在前端，刷新还原。
2. 没做登录，提交是匿名的。
3. 没做真实上传校验，九项检查只写了清单。
4. 没做 SGF 解析，回放用的是内置数组。
5. 没做审查后台。

## 下一版（o2）建议顺序

1. 把 `server.py` 接到这套前端，先让引擎列表、Elo、对局数据走真实接口。
2. 改参考平台的两个参数（komi 7.5、max_moves 500），计分换成固定裁判。
3. 加 SGF 上传与解析，回放改成读真实棋谱。
4. 再做提交表单的真实上传与九项校验。
5. 最后做审查后台。

顺序不能反：提交表单依赖数据结构，数据结构依赖榜单，榜单依赖对局记录，对局记录依赖裁判和 SGF。

## 本地服务（真跑对局）

静态页只能看，真跑要启服务：

```
python server.py
# 打开 http://127.0.0.1:8770/
```

依赖只有一个：`flask`（`pip install flask`）。首次运行自动创建 `engines/` 与 `data/`。

### 竞技场能做什么

| 动作 | 接口 | 说明 |
| --- | --- | --- |
| 上传引擎 | `POST /api/engines/upload` | 支持 .py / .exe / .zip。zip 会解压后自动找入口 |
| 握手校验 | 上传时自动 | protocol_version → boardsize 9 → komi 7.5 → clear_board → genmove |
| 开循环赛 | `POST /api/arena/start` | 每对局数可调，黑白各一局 |
| 查进度 | `GET /api/arena/state` | 进度、当前对局、逐局结果 |
| 查等级分 | `GET /api/ratings` | 按 Elo 降序 |
| 重置 | `POST /api/ratings/reset` | 清零，对局记录保留 |

### 对局流程（真跑，不是模拟）

1. 双方引擎各起一个 GTP 子进程，先后发 `boardsize 9`、`komi 7.5`、`clear_board`。
2. 轮流 `genmove`，每手计时，超过 5 秒判该方负。
3. 返回 `resign` 判负，返回非法坐标判负，互不接受落子判负。
4. 双方连续两次 `pass` 进终局。
5. 终局用 **GNU Go 3.8 重放全谱**并 `final_score`，只取它的死活判断，分数按数子法自己算。
6. 按 Elo 公式结算，K=32，写进 `data/ratings.json`。

### 已经实测跑通的数据

三台 GNU Go（不同 level）互打：

| 引擎 | 参数 | 战绩 | Elo |
| --- | --- | --- | --- |
| GNU Go L5 | `--level 5` | 4 局 3 胜 | 1026.4 |
| GNU Go L9 | `--level 9` | 2 局 1 胜 | 1004.1 |
| GNU Go L1 | `--level 1` | 2 局 0 胜 | 969.5 |

L5 两胜 L1（一局 W+7.5、一局 B+1.5），L9 与 L5 各胜一局。等级分变化与手算一致。

### 一个要说清楚的边界

**竞技场里的引擎和榜单页的示例引擎是两套东西。**

- 榜单页三个（go9x9 / minmaxgo9 / ZGo_final）是静态演示数据，用来展示界面结构，永远不参与对战。
- 竞技场里的是真引擎，真对局真 Elo，数据在 `engines.json` 和 `data/ratings.json`。

下一步要把两边打通：真实引擎要带 manifest（代数、干预、血统），才能进分组榜和口径榜。
